## 2. Архитектура

Текущей архитектуры хватает; её надо расширить, а не переписывать.

- **Стек:** Vite + React + TypeScript, PWA (`vite-plugin-pwa`) — без изменений.
- **Данные:** Dexie, схема версии 3 (миграция с v2 без потери данных):
  - `docs` — новые типы `subject`, `topic`, `lecture` (или поле `role` у папок), поля `icon`, `color`, `deletedAt` (корзина);
  - `lectureItems` — вкладки лекции: какой конспект, какая презентация/PDF, сводки, тесты;
  - `cards` — состояние «лестницы» интервалов (`step`, `due`, `lapses`) вместо полей FSRS, история — в существующем `reviewLogs`;
  - `tests`, `testAttempts` — тесты и результаты;
  - `ai` — кэш ответов ИИ и статус распознавания рукописи; поле `recognizedText` у рукописных блоков и страниц;
  - `glossary` — термины и определения (+ перевод), `dictionary` — офлайн-словарь китайского (загружается отдельным файлом);
  - `meta` — настройки (шрифт, провайдер ИИ, ключ, стрик).
- **Слой ИИ** (`src/features/ai`):
  - интерфейс `AiProvider { generate(prompt, {images, json}) }`, реализации `gemini.ts` (REST `generativelanguage.googleapis.com`, работает прямо из браузера) и `claude.ts` (Messages API с заголовком для браузера);
  - ключ хранится в IndexedDB на устройстве; понятные ошибки: нет сети, неверный ключ, лимит бесплатного уровня, сервис недоступен без VPN;
  - промпты — отдельные файлы `src/features/ai/prompts/*.md`, как просит этап 4;
  - ответы в строгом JSON (схема на каждую задачу) и проверка перед сохранением;
  - очередь задач: если сети нет, задача ждёт и выполняется позже (распознавание, сводки).
- **Pencil:** текущий холст (`perfect-freehand`, векторные штрихи) остаётся. Для свободного листа к штрихам добавляются «объекты» на листе: текстовые блоки и картинки с координатами. Автофигуры — распознавание по точкам штриха после паузы ~0,5 с. Пипетка — цвет ближайшего штриха.
- **PDF:** `pdfjs-dist` (уже есть). **PPTX** — см. риск 2.
- **Повторение:** чистая функция «лестницы» интервалов с тестами (`review/ladder.ts`) вместо FSRS.
- **Уведомления:** Cloudflare Worker (бесплатно) + Web Push (VAPID): приложение отправляет на сервер только время ближайших повторений (без содержимого карточек), Worker по крону шлёт push.

## 3. Технические риски PWA на iPad (Safari) и как их обходим

| # | Риск | Как обходим |
|---|---|---|
| 1 | iPadOS может удалить данные сайта, если его долго не открывать | Установка на «Домой» (тогда хранилище постоянное) + `navigator.storage.persist()` + ежедневная копия. Подсказка установки уже есть |
| 2 | **PPTX нельзя качественно отрисовать в браузере**: внутри только XML, готовых картинок слайдов нет (кроме миниатюры первого) | Варианта три: (а) рекомендовать экспорт презентации в PDF (PowerPoint/Keynote на iPad делают это в два нажатия) и работать с PDF; (б) свой упрощённый рендер PPTX — текст и картинки слайдов без точной вёрстки; (в) отдавать PPTX на сервер-конвертер. Предлагаю (а) + (б): PPTX открывается упрощённо, а для точного вида — PDF. См. вопрос 4 |
| 3 | Web Push на iPad работает только в установленной PWA (iPadOS 16.4+), после разрешения пользователя | Кнопка «Включить напоминания» в настройках после установки; запасной вариант — напоминание при открытии |
| 4 | Gemini недоступен из России без VPN; бесплатный уровень с лимитами | Понятное сообщение «нет доступа к Gemini — включите VPN» / «исчерпан лимит, попробуйте позже или переключитесь на Claude»; кэш ответов, чтобы не тратить лимит повторно |
| 5 | Ключ API в браузере может прочитать тот, у кого есть доступ к iPad | Только локально, не попадает в резервную копию (или по желанию); предупреждение в настройках |
| 6 | «Сохранить копию» с **тем же именем** через share sheet: iOS не заменяет файл молча, а спрашивает «Заменить / Сохранить оба» | Имя файла постоянное (`Мелькин-копия.zip`), в iCloud Drive достаточно один раз нажать «Заменить». Полностью без вопроса Safari это не умеет |
| 7 | «После полного закрытия — Сегодня, при возврате — последняя заметка»: Safari не сообщает, было ли приложение закрыто | `sessionStorage` очищается при закрытии PWA: если флага нет — это холодный старт, открываем «Сегодня» |
| 8 | Сканер доски (выпрямление): OpenCV.js весит ~8 МБ | Своя лёгкая реализация: поиск 4 углов по краям + перспективное преобразование на canvas + фильтр «контраст/белый фон»; углы можно подвинуть пальцем |
| 9 | Рисование без задержки при анимациях и тяжёлых страницах | Анимации только в повторении и на главной; холст не перерисовывает чужие слои; уже есть ленивая отрисовка страниц тетради и PDF |
| 10 | Объём: PDF, фото и офлайн-словарь китайского (десятки МБ) | Сжатие фото (уже есть до 2400 px), предупреждение при 80% квоты, словарь — по желанию отдельной загрузкой |
| 11 | Лицензия БКРС | Проверить на этапе 7; открытая альтернатива — CC-CEDICT (китайско-английский, CC BY-SA) с переводом определений на русский через ИИ при необходимости |
| 12 | Распознавание рукописи требует сети | Очередь: распознаём, когда появится сеть; распознанный текст хранится локально для офлайн-поиска |

## 5. Вопросы

   - а) ×2 каждый раз (2 нед → 1 мес → 2 мес…) — *предлагаю*;
   - б) ×2,5;
   - в) после недели — FSRS.

   И что делать с уже накопленной историей FSRS: пересчитать в шаги лестницы (*предлагаю*) или начать заново?
2. **Синтаксис карточек RemNote** (`>>`, `::`, `{{…}}`) — оставить для ручного создания карточек вместе с ИИ-генерацией?
   - а) оставить (*предлагаю*);
   - б) убрать, только ИИ и кнопки.
3. **Карточки с проверкой ИИ без сети** (в метро, на паре): что делать?
   - а) показывать ответ и самооценку «знаю / не знаю», как у двусторонних (*предлагаю*);
   - б) откладывать такие карточки до появления сети.
4. **PPTX:**
   - а) упрощённый показ PPTX + совет экспортировать в PDF для точного вида (*предлагаю*);
