# Как выложить Мелькина на GitHub и открыть на iPad

Пошагово, для человека, который делает это впервые. Займёт 20–30 минут. Платить ничего не нужно.

**Что получится в конце:** у приложения будет постоянный адрес вида `https://ВАШ-ЛОГИН.github.io/melkin/`. Его вы откроете на iPad, добавите на экран «Домой», и дальше приложение работает офлайн. Каждый раз, когда код обновляется, GitHub сам пересобирает сайт.

**Что важно понять заранее:**
- Ваши **конспекты и карточки на GitHub не попадают**. Туда уходит только код приложения. Данные живут на самом iPad (и отдельно на Mac).
- Репозиторий будет **публичным** — так бесплатный GitHub Pages работает. Код смогут видеть другие, но в коде нет ни ваших данных, ни ключа ИИ (ключ хранится только на устройстве).
- Сайт с кодом — это «коробка» для приложения. Если её обновить, данные внутри iPad остаются.

---

## Часть 1. Аккаунт на GitHub (5 минут)

1. Откройте **https://github.com** → **Sign up**.
2. Введите почту, придумайте пароль и **логин** (username) — латиницей, например `melkina`. Логин будет частью адреса приложения, выбирайте короткий и без точек.
3. Подтвердите почту кодом из письма.
4. На вопросы анкеты можно ответить как угодно или пропустить. Тариф — **Free**.

> Дальше везде, где написано `ВАШ-ЛОГИН`, подставляйте этот логин.

## Часть 2. Пустой репозиторий (3 минуты)

Репозиторий — это «папка проекта» на GitHub.

1. Справа вверху нажмите **«+»** → **New repository**.
2. **Repository name**: `melkin` (латиницей, маленькими буквами, без пробелов). Это имя войдёт в адрес: `https://ВАШ-ЛОГИН.github.io/melkin/`.
3. **Public** — обязательно публичный (иначе бесплатный Pages не работает).
4. **Ничего не отмечайте** ниже: ни «Add a README», ни «.gitignore», ни «license». Репозиторий должен быть совсем пустым.
5. Нажмите **Create repository**. Откроется страница с подсказками — оставьте её открытой.

## Часть 3. Включите публикацию сайта (1 минута) — до загрузки кода!

1. В репозитории откройте вкладку **Settings** (шестерёнка вверху).
2. Слева — **Pages**.
3. В блоке **Build and deployment** → **Source** выберите **GitHub Actions**.
4. Больше ничего не трогайте — сохранять не нужно, выбор применяется сразу.

> Если пропустить этот шаг, первая публикация упадёт с ошибкой. Ничего страшного — включите и перезапустите её (см. «Если что-то пошло не так»).

## Часть 4. Загрузите код — выберите ОДИН из двух способов

### Способ А (проще): приложение GitHub Desktop

> ⚠️ Две ловушки GitHub Desktop:
> - **Имя.** Папка называется по-русски, а GitHub кириллицу не принимает — из «Мелькин <3» получится имя **`-3`**. В окне Publish впишите имя `melkin` вручную.
> - **Приватность.** Галочка «Keep this code private» стоит по умолчанию — **снимите её**. С приватным репозиторием бесплатный сайт не публикуется.
>
> Если уже опубликовали с именем `-3` и/или приватным — ничего страшного, исправляется за минуту: см. «Если что-то пошло не так» → строки про имя `-3` и «приватный».

Не нужны ни Терминал, ни токены.

1. Скачайте **GitHub Desktop**: https://desktop.github.com → установите (перетащите в «Программы») → откройте.
2. **Sign in to GitHub.com** → в браузере войдите в свой аккаунт → **Authorize** → вернитесь в приложение.
3. На шаге «Configure Git» оставьте имя и почту как предлагает (или впишите свои) → **Finish**.
4. Меню **File → Add Local Repository…** → **Choose…** → выберите папку проекта **«Мелькин <3»** на рабочем столе → **Add Repository**.
   - Если приложение пишет «This directory does not appear to be a Git repository» — вы выбрали не ту папку. Нужна именно папка, где лежат `package.json`, `README.md`, папка `src`.
5. Вверху должно быть: **Current Repository: Мелькин <3**, **Current Branch: main**.
6. Нажмите синюю кнопку **Publish repository** (вверху справа).
   - В окне **уберите галочку «Keep this code private»** (иначе он станет приватным — тогда сайт не опубликуется бесплатно).
   - Name: `melkin`. Но мы уже создали пустой `melkin` в части 2 — GitHub Desktop может сказать, что такое имя занято. Тогда сделайте так:
     1. Закройте окно Publish.
     2. Меню **Repository → Repository Settings… → Remote** → в поле **Primary remote repository (origin)** вставьте `https://github.com/ВАШ-ЛОГИН/melkin.git` → **Save**.
     3. Нажмите вверху **Push origin** (или **Publish branch**).
7. Готово, переходите к части 5.

> Совет: можно пропустить часть 2 и сразу нажать **Publish repository** — GitHub Desktop сам создаст репозиторий `melkin`. Главное — снять галочку «Keep this code private». А часть 3 (Pages) сделайте сразу после публикации.

### Способ Б: через Терминал

1. Откройте **Терминал** (Spotlight: ⌘ + пробел → «Терминал»).
2. Перейдите в папку проекта (скопируйте строку целиком, с кавычками):
   ```bash
   cd ~/Desktop/"Мелькин <3"
   ```
3. Проверьте, что всё сохранено (коммиты сделаны):
   ```bash
   git status
   ```
   Должно быть `nothing to commit, working tree clean`.
4. Подключите GitHub (вместо `ВАШ-ЛОГИН` — ваш логин):
   ```bash
   git remote add origin https://github.com/ВАШ-ЛОГИН/melkin.git
   ```
5. Отправьте код:
   ```bash
   git push -u origin main
   ```
6. Git спросит **Username** — введите логин GitHub. Затем **Password** — тут нужен **не пароль, а токен**:
   1. На GitHub: аватар справа вверху → **Settings** → в самом низу слева **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
   2. Note: `Мелькин`, Expiration: `90 days` (или `No expiration`), отметьте галочки **repo** и **workflow**.
   3. **Generate token** → скопируйте строку `ghp_…` (её покажут один раз).
   4. Вставьте её в Терминал вместо пароля (символы при вводе не видны — это нормально) → Enter.
7. Увидите строки `Writing objects… 100%` и `main -> main` — код загружен.

> Токен — как пароль. Не пересылайте его никому и не вставляйте в чаты. macOS сохранит его в «Связке ключей», вводить заново не придётся.

## Часть 5. Дождитесь публикации (2–4 минуты)

1. В репозитории откройте вкладку **Actions**.
2. Там появится запуск **Deploy to GitHub Pages** с жёлтым кружком — идёт сборка: установка, **тесты (≈200 штук)**, сборка, публикация.
3. Через 2–4 минуты кружок станет **зелёной галочкой** ✓.
4. Откройте **Settings → Pages** — вверху будет написано **«Your site is live at https://ВАШ-ЛОГИН.github.io/melkin/»**. Нажмите **Visit site** — откроется Мелькин.

## Часть 6. Установите на iPad (3 минуты)

1. На iPad откройте **Safari** (именно Safari, не Chrome) → адрес `https://ВАШ-ЛОГИН.github.io/melkin/`.
2. Подождите 10–20 секунд, пока приложение скачается целиком (внизу появится «Приложение сохранено и теперь работает без интернета»).
3. Кнопка **«Поделиться»** (квадрат со стрелкой) → **«На экран „Домой“»** → **Добавить**.
4. Дальше **всегда открывайте Мелькина значком с экрана «Домой»**, а не во вкладке Safari: у значка своё хранилище, iPadOS его не чистит, и только так работают уведомления.

## Часть 7. Перенесите то, что уже есть (если нужно)

Данные хранятся **отдельно для каждого адреса**: у `localhost:5174` на Mac (где вы смотрели приложение раньше) — одна база, у нового сайта на iPad — другая, пока пустая.

Чтобы перенести конспекты с Mac:
1. На Mac откройте старый адрес (`localhost:5174`, при запущенном `npm run dev`) → **Настройки → Сохранить копию** → файл `Мелькин-копия.zip`. Сохраните его в iCloud Drive (или отправьте себе через AirDrop).
2. На iPad в Мелькине (значок на «Домой») → **Настройки → Восстановить из файла** → выберите этот файл → **«Заменить всё»** (база на iPad пока пустая) или **«Объединить»**.
3. Ключ ИИ и китайский словарь в копию не входят — вставьте ключ заново в «Настройках», словарь загрузите в «Словарь → Китайский словарь».

## Часть 8. Обновления в будущем

Когда код меняется (например, Claude Code что-то исправил):
- **GitHub Desktop**: внизу слева впишите короткое описание → **Commit to main** → вверху **Push origin**.
- **Терминал**: `cd ~/Desktop/"Мелькин <3"` → `git push`.
- Или просто попросите Claude Code: «закоммить и запушь».

Через 2–3 минуты (вкладка **Actions** — зелёная галочка) откройте Мелькина на iPad с интернетом → внизу плашка **«Доступна новая версия» → «Обновить»**. Подробнее — `docs/UPDATE.md`.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| В **Actions** красный крестик на шаге **deploy**: «Get Pages site failed» / «Not Found» | Не включён Pages (часть 3). Включите **Settings → Pages → Source: GitHub Actions**, затем **Actions** → откройте упавший запуск → **Re-run all jobs** |
| Красный крестик на шаге **npm test** | Какой-то тест упал — сайт не обновился, старая версия работает. Откройте запуск, скопируйте текст ошибки и покажите Claude Code |
| Красный крестик на шаге **npm ci** / **build** | Тоже покажите текст ошибки Claude Code. Частая причина — временный сбой GitHub: попробуйте **Re-run all jobs** |
| `git push`: «Authentication failed» / «Password authentication is not supported» | Вместо пароля нужен **токен** (часть 4, способ Б, шаг 6). Или воспользуйтесь GitHub Desktop |
| `git push`: «remote origin already exists» | Origin уже добавлен. Проверьте адрес: `git remote -v`. Исправить: `git remote set-url origin https://github.com/ВАШ-ЛОГИН/melkin.git` |
| `git push`: «rejected… fetch first» / «non-fast-forward» | Репозиторий на GitHub создан не пустым (с README). Проще всего удалить его (**Settings → внизу Delete this repository**) и создать заново пустым (часть 2) |
| `git push`: «refusing to allow… workflow… without `workflow` scope» | При создании токена не отмечена галочка **workflow**. Создайте новый токен с **repo** и **workflow** |
| Сайт открывается, но **пустая белая страница** | Имя репозитория в адресе должно совпадать: `…github.io/melkin/` для репозитория `melkin`. Обновите страницу через минуту после зелёной галочки |
| Сайт показывает **404** | Подождите 1–2 минуты после первой публикации. Проверьте, что адрес заканчивается на `/melkin/` (со слешем) |
| Кнопка «Загрузить» китайский словарь пишет ошибку | При сборке GitHub не смог скачать словарь с mdbg.net (временный сбой). **Actions → Re-run all jobs** — он скачается при следующей сборке |
| Репозиторий опубликован **приватным** (на github.com рядом с именем значок 🔒 **Private**) | **Settings** → в самом низу **Danger Zone** → **Change repository visibility** → **Change to public** → подтвердите. Затем **Settings → Pages → Source: GitHub Actions** и **Actions → Deploy to GitHub Pages → Run workflow → Run workflow** |
| Репозиторий называется **`-3`** | **Settings** → вверху **Repository name** → впишите `melkin` → **Rename**. GitHub Desktop подхватит новое имя сам (или попросите Claude Code обновить адрес). Делайте это до установки на iPad |
| Хочу переименовать репозиторий | Можно (**Settings → General → Repository name**), но адрес сайта изменится, и **на iPad будет новое пустое приложение**. Сначала сохраните копию, потом восстановите её на новом адресе |

## Что хранится где — коротко

| Что | Где | Попадает на GitHub? |
|---|---|---|
| Код приложения | Папка «Мелькин <3» на Mac → GitHub | Да |
| Конспекты, тетради, карточки, тесты, словарь терминов | IndexedDB на каждом устройстве | **Нет** |
| Резервная копия | `Мелькин-копия.zip` в iCloud Drive | Нет |
| Ключ ИИ | Только на устройстве | **Нет** (и в копию тоже не входит) |
| Сервер напоминаний | Ваш Cloudflare Worker (`docs/PUSH.md`) | Код сервера — да, ключи — нет |
